# X Spam Blocker — Design Spec

- 状态：v2.1（对应脚本 v0.7.1）
- 权威源：本文件。版本演进只改本文件，不另起带日期的副本。
- 代码：`x-spam-blocker.user.js`（Tampermonkey 单文件）；回归：`npm test`

## 0. 三句话摘要

- **解决什么**：移动端 X App 不支持运行此用户脚本，评论区可能出现批量变体垃圾回复。屏蔽与静音都是**账号级服务端状态**，在手机上同样生效，所以方案 = 桌面端把「一批号说同一句话」识别出来，一次确认、慢速执行，手机端只消费结果。
- **最坏情况**：① 误判真人（可逆：账本记录 + 撤销）；② X 判定为脚本操作站点而限制账号（X 自动化规则明文禁止脚本化操作网站，**不可逆风险最大项**，靠「必须人工确认 + 限速 + 触顶即停 + 出错即停」压住）；③ X 改 DOM 让脚本静默失效（回归测试 + 启动日志可观测）。
- **回滚开关**：面板把动作切回「只标记」即刻停止一切写请求（已发出的不撤回）；账本「撤销」只对记为成功的条目可用，且解除的是当前这层关系（可能含用户先前自己设的静音/屏蔽）。代码级回滚 = 以**更高版本号**发布恢复后的行为（Tampermonkey 只认版本号递增，不能靠退版本回滚）。

## 1. 问题的机制层结论

X 的 block / mute 都是服务端账号关系，任何客户端生效——这是唯一能让手机评论区变干净的杠杆。X 帮助文档明确：**你未关注的已静音账号，其回复在你打开会话时被隐藏**；block 更重，还会切断关注关系且解除后不自动恢复。

v0.6.7 的三个结构性短板与 v2.1 对策：

| 短板 | 后果 | v2.1 对策 |
|---|---|---|
| 关键词表追变体（同音混淆） | 每波新话术都要人工补词 | ① 归一化 + ② 模板指纹聚类（不认字，认「多个号说同一句话」）——**只作标记与复核证据，不单独授权自动动作** |
| 只有 block 一种动作 | 无更轻的可逆选项 | ③ 动作可选 block / mute，默认 block |
| `MODE` 写死在源码 | 自动更新一到，用户改的 `auto` 被覆盖 | ④ 设置持久化 + 面板开关 |
| 屏蔽没有账本 | 误判无法追溯与撤销 | ⑤ 账本：意图→结果两段记录，可撤销、可导出 |

**明确不在 v0.7.0 的**：无人值守巡逻（自动滚动、自动展开回复、自动出手）、设备定时运行、由簇触发的自动屏蔽。理由：X 自动化规则禁止脚本化操作站点并警告可永久封禁；分类器在「真人复读同一句话 + 同形态 handle」时无法与垃圾号区分。此版本不提供无人值守写入功能。

## 2. 组件与职责（v2.1）

```
[X 页面 DOM] ──MutationObserver──▶ 抽取层 extract()   作者本人文本 ≠ 引用推文文本（引用内容不计入作者定罪）
                                        │
                                        ▼
                               归一化层 normalize()    ① 先摘出 @提及与 URL → NFKC → 去 emoji/零宽/变体选择符
                                        │                 → 去标点/空白 → 去 1–3 位孤立字母数字尾码 → 小写 → 极小同形表
                     ┌──────────────────┴──────────────────┐
                     ▼                                     ▼
            单卡评分 score()                       模板指纹簿 TemplateBook（按会话页 + 观察窗分桶）
            （v0.6.7 全部信号保留）                  同一归一化文本下 ≥3 个不同作者 ⇒ 簇证据
                     └──────────────────┬──────────────────┘
                                        ▼
                     判定：总分 ≥ THRESHOLD ⇒ 标红 + 「屏蔽/静音」按钮（簇成员标注「簇×N」）
                                        │
                              人工确认（单击 / 本页批量）
                                        ▼
                               共享准入控制 Admission     所有写路径共用：随机间隔、小时/日尝试计数、
                                        │                 429/401/403/未知结果 ⇒ 暂停并显示原因
                                        ▼
                               动作执行 block | mute      ③ 面板可选；默认 block
                                        ▼
                               账本 Ledger                ⑤ 意图 → 结果（成功/失败/未知）；撤销只对成功项
```

### ① 归一化 normalize(text)
- 顺序（保留 `@` 分隔符直到提及提取完成）：先用正则摘出 `@handle` 与 URL 并移除 → NFKC → 去 `\p{Extended_Pictographic}`、ZWJ、变体选择符 → 去标点与空白 → 去孤立的 1–3 位字母/数字尾码（`1e`、`5d` 之类的批次码）→ 小写 → 同形小表（`貨→货`、`沒→没`、`sao→骚`）。不做 `✈→打飞机` 之类改变语义的映射；保留其它数字。
- 仅用于模板指纹；`score()` 的关键词匹配继续用原文。

### ② 模板指纹聚类 TemplateBook
- 分桶键 = 当前会话页（`/status/<id>` 的 id，首页为 `home`）；每桶 LRU ≤ 500 模板，每模板作者集合 ≤ 50，全局 ≤ 2000 模板。观察窗 = 页面生命周期（路由切换即清空该桶）。
- 入簇条件：归一化文本长度 ≥ 8 且不同字符数 ≥ 4；同键下**不同作者** ≥ `CLUSTER_MIN`（默认 3）。
- 簇成员得 `W.cluster`（默认 3）；**簇分只参与标记判定**：自动模式下，簇分不计入自动出手门槛（自动出手仍只认 v0.6.7 的独立信号）。真人粉丝团刷同一句口号最多被标红供复核，不会被自动处理。
- 簇形成或设置变更时，用「证据版本号」使已缓存的卡片签名失效并回扫（需追踪所有已见卡片，按 handle 有界）。
- 不把某成员的其它证据转移给其它成员。

### ③ 动作层 action = block | mute
- 默认 `block`，`mute` 可选（`POST /i/api/1.1/mutes/users/create.json`，`screen_name=`）。v0.7.1 保持既有屏蔽行为；两者请求形态均使用当前登录会话的认证信息。
- mute 端点参数与移动端可见效果尚未完成端到端验证，不能将其描述为已验证的默认替代方案。

### 共享准入控制 Admission
- 所有写路径（单击、批量、撤销）经同一队列：随机间隔 6–12 秒（v0.6.7 已上线值），「下次允许发送时刻」持久化供多标签共享，发送前再次读取上限与时刻；计**尝试次数**：小时 ≤ 40、日 ≤ 150（持久化，跨刷新有效）。这些数字是保守工程估计，不是 X 公布的安全阈值。
- 收到 429 / 401 / 403 / 网络异常 ⇒ 队列暂停、面板显示原因、清空未发项（已发出的标记为「结果未知」）；不自动恢复。
- 队列条目绑定 handle 与证据，不持有 DOM 引用；路由切换时清空未发项。

### ④ 设置持久化 Settings
- `localStorage['xspam.settings.v1']`：`{mode:'mark'|'auto', action:'mute'|'block', threshold}`；schema 校验，非法值回落默认；存储不可用时用内存值且面板提示。
- 面板：模式切换、动作切换、账本导出、撤销最近一条。

### ⑤ 账本 Ledger
- `localStorage['xspam.ledger.v1']`：每条 `{handle, userId?, action, score, reasons, page, at, status:'intent'|'ok'|'fail'|'unknown'|'undone'}`；上限 2000 条 FIFO，淘汰时面板提示「更早的记录已不可撤销」。
- 撤销：先从存储合并最新账本再选最近的 `status==='ok'` 项，发送前按 id 重读并核状态仍为 ok，再调用对应 destroy 端点（有 `userId` 时按 id，否则按 handle）。🔴 撤销 = 解除「现在这层关系」，不是回退脚本动作：X 的 create 端点幂等，脚本无法得知动手前是否已存在同一关系，因此撤销可能解除用户先前自己设置的静音/屏蔽（README 已说明这一限制）。
- 多标签：账本每次持久化前重读存储并按条目 id 合并；请求带 20 秒超时：响应头之前超时记 `unknown` 并暂停队列；已收到成功响应头、读响应体时超时的，动作已在服务端生效，记 `ok` 但同样暂停队列。
- 导出：复用采集器的下载通道。

## 3. 失败模式与对策

| 失败模式 | 触发 | 对策 / 可观测 |
|---|---|---|
| 误判真人 | 粉丝团/梗复读 + 同形态 handle | 簇只标记不自动出手；账本可撤销；需要更轻的可切 mute |
| X 账号限制 | 写请求过多 / 被识别为脚本 | 人工确认前置；共享限速与日上限；出错即停不重试 |
| DOM 改版 | 选择器失效 | 启动日志 + 面板存在性；回归测试锁选择器 |
| 引用推文误归属 | 引用垃圾回复的真人被当作作者 | 抽取只取作者本人文本，引用块排除 |
| 缓存决策过期 | 簇形成后旧卡不重判 | 证据版本号使签名失效 |

## 4. 验证意图（回归测试必须覆盖）

1. 「我福不黑不信你看」类变体：3 个同形态 handle 发同一句（带不同 emoji/尾码）⇒ 全部标记且标注簇；单独 1 个（无其它信号）⇒ 不标。
2. 3 个正常 handle 回同一句无旁证 ⇒ 不标；3 个同形态 handle 回一句长口号（无其它信号）⇒ 标红但**自动模式不入队**。
3. 引用推文：真人引用一条垃圾回复 ⇒ 不标。
4. 归一化：emoji/尾码/全角/同形差异不破坏模板相等；`@` 提及先被摘出。
5. 设置持久化：写入 `auto`/`block` 后重新启动脚本仍生效；非法值回落默认。
6. 账本：动作先写 intent，成功后改 ok；撤销调用对应 destroy 端点；失败/异常状态不可撤销。
7. 准入：429 后队列暂停且不再发送；小时/日尝试上限触顶后不再入队。
8. 原 14 用例全部保留；版本号与元数据一致。
9. 测试 harness 需要可控时钟（定时器不再立即执行）与可编程 fetch 结果。

## 5. 非目标

- 无人值守巡逻 / 设备定时运行 / 簇触发自动出手（见 §1 的风险边界）。
- 云端共享黑名单；LLM 语义层；iOS Userscripts App 适配。
- X 关键词静音（帮助文档对是否覆盖会话回复自相矛盾，须先实测再决定接不接）。
